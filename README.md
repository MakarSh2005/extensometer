# Видеоэкстензометр для Shimadzu AG-X plus

Измеряет удлинение ΔL образца по видео с обычной камеры (веб-камера, USB-камера, телефон),
находит момент разрыва и L2 — расстояние между метками в последнем кадре, где перемычка
(шейка) ещё цела. С машиной не синхронизирован: видео обрабатывается после испытания,
а при необходимости совмещается с её CSV (сила–время).

## Приложение (без консоли)

Запуск: `Extensometer\Extensometer.exe` из собранной папки (см. «Пересобрать exe» ниже) или `python app.py`.
Собранному exe Python не нужен — папку `Extensometer` целиком можно скопировать на компьютер у машины.

1. **Источник.** «Открыть видео…» или «Включить камеру» → «Начать запись» (до старта машины) →
   «Остановить запись» после разрыва. Записанное видео откроется автоматически.
   Записи по умолчанию сохраняются в `Extensometer\records`.
2. **Параметры.** L0 в мм, метод трекинга, «Следить за шейкой» — включено по умолчанию.
3. **Метки.** Ползунком выберите кадр до начала растяжения → «Указать метки на видео» →
   клик по верхней и нижней метке. Анализ начнётся с этого кадра.
4. **Анализ.** «Запустить анализ». После него видео встанет на кадр L2. Листайте ←/→
   (PgUp/PgDn — по 10 кадров), при необходимости «Назначить L2 = текущий кадр».
   Клик по графику переходит к этому моменту видео.
5. **Кривая F–ΔL.** Вкладка «Кривая F–ΔL» → загрузить экспорт машины → столбцы
   времени и силы подставятся сами → «Построить кривую».

### Телефон вместо камеры

- **Запись на телефон (рекомендуется).** Снимайте обычной камерой телефона (1080p или 4K, 30 fps),
  зафиксируйте фокус и экспозицию долгим нажатием на образец, перенесите файл на компьютер и
  откройте его «Открыть видео…». Время кадров берётся из самого файла. На iPhone выберите
  Настройки → Камера → Форматы → «Наиболее совместимый» (H.264).
- **Телефон как веб-камера по Wi‑Fi** (DroidCam, IP Webcam — Android; DroidCam, EpocCam — iPhone):
  введите в поле «Камера № или адрес» адрес, который показывает приложение на телефоне
  (например `http://192.168.1.25:4747/video`), и нажмите «Включить камеру».
- **Телефон как веб-камера по USB или через «Связь с телефоном» Windows 11** — телефон
  появляется как обычная камера: выберите её номер (1, 2…).

Все результаты сохраняются автоматически в папку `<имя видео>_results` рядом с видео
(кнопка «Папка результатов»).

Пересобрать exe из исходников:

```bash
pip install -r requirements.txt pyinstaller
pyinstaller --noconfirm --windowed --onedir --name Extensometer app.py
```

## Подготовка испытания (от этого зависит точность)

1. **Метки.** Нанесите на образец две контрастные точки (тонкий чёрный маркер, Ø 1–2 мм) на
   расчётной длине L0 (например, 50 мм), по оси образца. Для тёмных образцов — белый маркер
   и флаг `--bright-marks`.
2. **Камера** — на штативе, **перпендикулярно** образцу, неподвижно. Образец с метками должен
   занимать как можно большую часть кадра по высоте, с запасом на удлинение.
3. **Фокус и экспозиция — ручные** (`--focus`, `--exposure`). Автофокус «дышит» и меняет масштаб.
4. **Фон** за образцом — контрастный (чёрная бумага за светлым металлом). Нужен для поиска шейки.
5. **Свет** — ровный, без бликов на метках.

Разрешение: при 1080p и поле зрения ~100 мм на 1 пиксель приходится ~0.09 мм; трекинг
субпиксельный (~0.05 px), т.е. порядка 5 мкм в идеальных условиях. На практике
точность ограничат вибрации, освещение и перпендикулярность камеры.

## Работа

### 1. Запись

```bash
python extensometer.py record --camera 0 --out test1.avi
```

Включите запись **до** старта машины, остановите (Q/Esc) после разрыва. Рядом создастся
`test1.ts.csv` с точным временем каждого кадра (веб-камеры часто пишут с неровным FPS).
Можно снимать и чем угодно другим — тогда время берётся из FPS видеофайла.

### 2. Обработка

```bash
python extensometer.py analyze test1.avi --l0-mm 50 --neck
```

- Кликните по метке 1, затем по метке 2 и нажмите Enter (Backspace — отменить клик).
  Размер метки программа находит сама. Выделение рамкой вместо клика — флаг `--box`.
- Программа отследит метки по всем кадрам, найдёт разрыв и откроет окно проверки:
  **A/D** (или ←/→) — кадр назад/вперёд, **Z/C** — на 10 кадров, **Enter** — выбрать
  текущий кадр как последний перед разрывом, **Esc** — оставить автоматический.

Масштаб (одно из):
- `--l0-mm 50` — метки нанесены на известном расстоянии (рекомендуется);
- `--calib-mm 100` — кликнуть две точки на линейке в кадре;
- `--mm-per-px 0.0912` — готовый масштаб.

Разрыв определяется по первому из признаков:
- ширина перемычки между метками упала до 0 (`--neck`);
- скачок L между кадрами (упругая разгрузка частей при разрыве);
- потеря метки (часть образца улетела из кадра).

Результаты в `test1_results/`:

| файл | содержимое |
|---|---|
| `test1_ext.csv` | покадрово: время, координаты меток, L, ΔL, ε, ширина шейки |
| `test1_summary.json` | L0, L2, ΔL при разрыве, ε при разрыве, кадр/время L2, старт движения |
| `test1_L2_frame.png` | кадр L2 с разметкой — для протокола |
| `test1_plot.png` | ΔL(t) и ширина шейки(t) |

Для повторной обработки без мыши ROI печатаются в консоль: `--roi1 x,y,w,h --roi2 x,y,w,h`.

### 3. Совмещение с данными машины (кривая F–ΔL)

Экспортируйте из Trapezium X таблицу «время – сила» в CSV и выполните:

```bash
python extensometer.py merge test1_results/test1_ext.csv machine.csv --time-col 0 --force-col 1 --skip-rows 0
```

Столбцы можно задать номером (с 0) или именем. Строки с единицами измерения пропускаются,
десятичная запятая и разделитель `;` поддерживаются.

Часы камеры и машины не связаны, поэтому время совмещается по событию:
- `--align break` (по умолчанию) — момент разрыва (резкое падение силы ↔ кадр L2);
- `--align start` — начало нагружения ↔ начало движения меток;
- `--align both` — по обоим, корректирует и сдвиг, и разницу хода часов;
- `--align offset --offset 12.4` — вручную.

Результат: `test1_merged.csv` (t, F, ΔL, ε) и график `test1_merged.png`.

## Методы трекинга

- `--method blob` (по умолчанию) — центр тяжести тёмного пятна. Лучше всего для
  нарисованных точек, устойчив к их вытягиванию при больших деформациях.
- `--method template` — корреляционное сопоставление шаблона. Для наклеек, рисок, любой
  текстуры; шаблон автоматически обновляется при деформации метки.

## Проверка на синтетике

```bash
cd demo
python make_test_video.py
python ../extensometer.py analyze demo.avi --l0-mm 50 --roi1 620,180,40,40 --roi2 620,500,40,40 --neck --no-review
python ../extensometer.py merge demo_results/demo_ext.csv demo_machine.csv --time-col Time --force-col Force
```

Генератор создаёт видео растяжения с шейкой и разрывом и знает истинные значения
(`demo_truth.json`): ΔL = 16.749 мм, разрыв после кадра 214. Программа находит
ΔL = 16.750 мм, кадр 214; ошибка трекинга до разрыва — 0.03 px RMS. Сдвиг часов
«машины» (7.30 с) восстанавливается как 7.297 с (точность — один кадр).

## Ограничения

- Метки должны быть видны всё испытание; не наносите их у самых захватов.
- Деформация измеряется в плоскости кадра. Если камера стоит под углом, масштаб по оси
  искажается — ставьте её перпендикулярно и калибруйте по `--l0-mm`.
- Поиск шейки предполагает, что образец контрастен фону и полоса анализа
  (`--neck-halfwidth`) шире образца — программа предупредит, если это не так.
